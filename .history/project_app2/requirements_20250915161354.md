 Scope of Work ถ้าเราจะวางแผนพัฒนาแอปด้วย **Flutter + Supabase** ควรแบ่งออกเป็น **3 ระดับการวางแผน**: **Data Layer, Workflow/UI, และ Integration**

---

## 1. Data Layer (Supabase)

Supabase จะเป็นฐานข้อมูลหลัก (PostgreSQL + API + Auth)
เราต้องออกแบบ Schema ให้รองรับข้อมูลที่อยู่ในสไลด์:

### ตารางที่ต้องมี

1. **SKU Table**

   * tsmf\_part\_number (string)
   * customer\_part\_number (string)
   * part\_name (string)
   * material\_grade (string)
   * customer\_name (string)
   * weight\_per\_piece (float)
   * pcs\_per\_packaging (int)

2. **Container Table**

   * container\_id (string เช่น S001, B001)
   * weight (float)

3. **User Table**

   * user\_id (uuid, auth binding)
   * name (string)
   * role (operator, qc, admin)

4. **Transaction / Weighing Log**

   * id (uuid)
   * date\_time (timestamp)
   * sku\_id (fk to SKU)
   * container\_id (fk to Container)
   * gross\_weight (float)
   * net\_weight (calc)
   * pieces (calc)
   * delivery\_date
   * lot\_no
   * cic\_no (11 digits)
   * user\_id (fk to user)

5. **QC / Config Table (optional)**

   * hi\_value, lo\_value (range checking)
   * label\_template (json, html-like)

## 2. Workflow + UI (Flutter)

Flutter จะทำหน้าที่ **Input / Output + Scan + Scale Integration**

### Workflow ตามสไลด์

1. Load SKU → ค้นหาด้วย **ID หรือชื่อ**
2. แสดงข้อมูล: ID, Name, Weight/PCS, PCS/Packaging
3. Load container → ด้วย ID หรือสแกน QR
4. อ่านค่าชั่งน้ำหนัก (scale) → ผ่าน Serial / TCP / BLE (ขึ้นอยู่กับเครื่อง)
5. คำนวณ: `(Gross - Container) / UW`
6. User กรอกข้อมูลเพิ่ม → Delivery date, Lot no, Raw batch, CIC no
7. บันทึก → Supabase (transaction log)

### UI Modules

* **Login** (Supabase Auth)
* **Dashboard / Menu** (คล้าย WeWeigh → chart, graph)
* **Weighing Screen**

  * SKU select
  * Container select
  * Scale reading
  * Input delivery / lot
  * Calculate & Save
* **Report Viewer**

  * Date range filter
  * Export CSV/Excel
* **QC Check**

  * Alert ถ้าน้ำหนักนอกช่วง
* **Label Print**

  * Fixed format (10x6 cm)
  * QR code confirm data

---

## 3. Integration & Reports

1. **Reports**

   * Supabase function/SQL view สำหรับ join ตาราง
   * Export → CSV, Excel, PDF
   * Graph/Histogram → Flutter side (charts\_flutter, syncfusion, etc.)

2. **Realtime Sync**

   * Supabase Realtime → update logs & dashboard ทันที
   * Write data line → Cloud simultaneously

3. **ERP Integration (Future)**

   * เตรียม API endpoint → Webhook (REST/GraphQL)
   * ERP จะดึงผ่าน Webhook

4. **Printing**

   * ใช้ library เช่น `esc_pos_utils` (Bluetooth/WiFi printer)
   * Layout → Fixed 10x6 cm
   * Generate QR → `qr_flutter`

---

## 4. Roadmap การพัฒนา

### Phase 1 – Prototype (2–3 สัปดาห์)

* Schema บน Supabase
* Flutter App: Login + SKU select + Container select + Manual weight input
* Save Transaction Log
* Basic Report (table view)

### Phase 2 – Scale Integration + Label (3–4 สัปดาห์)

* Connect scale → Serial/TCP/Bluetooth
* Auto calculate net weight + pieces
* Print label (10x6 cm + QR)
* QC range check

### Phase 3 – Dashboard + Report + API (4–6 สัปดาห์)

* Chart/Graph/Histogram (เหมือน WeWeigh)
* Export CSV/PDF
* ERP API / Webhook integration

---
